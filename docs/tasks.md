# ひろまち 実装タスク

## 1. 進め方

- 未完了タスクは上から順に進めます。
- 作業前に関連する設計書と既存コードを確認します。
- 1回の変更を小さく保ち、変更した振る舞いに対応するテストを追加・更新します。
- 作業後は少なくとも関連テストを実行し、完了時は全テストを実行します。
- 完了条件を満たした項目だけを`[x]`へ変更します。
- 任意バックログは、必須作業と利用者テストが完了するまで着手しません。

## 8. 次に行う作業

- [ ] ローカル開発用の環境変数を設定する。
  - 実施：`.env.example`を`.env`へコピーし、ランダムな`SECRET_KEY`を設定する。
  - 完了条件：秘密情報がGit管理されず、設定エラーなくアプリを起動できる。

- [ ] 開発用データベースを初期化する。
  - 実施：`flask --app hiromachi init-db`を実行する。
  - 完了条件：現在の5テーブルとゴミ種類4件が作られ、再実行しても重複しない。

- [ ] ブラウザーで主要導線を手動確認する。
  - 実施：登録、ログイン、活動登録、一覧、詳細、マイページ、ログアウトを順番に操作する。
  - 完了条件：画面遷移、メッセージ、保存内容に問題がなく、ブラウザー再読込で二重登録されない。

- [ ] スマートフォン幅で表示を確認する。
  - 実施：幅360px前後で全画面、ナビゲーション、フォーム、活動カードを確認する。
  - 完了条件：横スクロールや重なりがなく、主要ボタンと入力欄を操作できる。

- [ ] 初回利用者テストを行う。
  - 実施：想定利用者に主要導線を操作してもらい、迷った箇所と感想を記録する。
  - 完了条件：確認日、対象者（匿名可）、完了できた操作、迷った点、感想、修正候補をこの項目の下へ追記する。

- [ ] 利用者の反応を要件へ反映する。
  - 実施：フィードバックを必須修正と任意改善に分ける。
  - 完了条件：実装前に`requirements.md`、必要な設計書、タスクを更新する。`lean_canvas.md`は更新しない。

## 9. 任意バックログ

追加機能は、利用者の必要性を確認し、要件と設計を更新した後だけ着手します。

- [x] 活動写真を1枚添付する。
  - 実装：任意のJPEG・PNG・WebPを1枚、5MB以内で受け付け、投稿前プレビューを表示し、長辺2000px以内へ縮小して詳細画面で表示する。
  - 確認：画像の検証、認証付き配信、保存失敗時の後片付けを自動テストで確認済み。

  - 条件：認可、更新日時、削除確認、関連データの扱いを先に設計する。

- [ ] その他の将来機能を選定する。
  - 条件：利用者から具体的な要望が得られるまで、地図、ランキング、交流、通知などを実装しない。
