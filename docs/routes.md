# ひろまち ルーティング設計書

## 1. この文書について

この文書は、「ひろまち」初版（MVP）のFlaskルート、HTTPメソッド、認証、正常時とエラー時の処理を定めるものです。画面の表示内容は`docs/screens.md`、機能要件は`docs/requirements.md`を基準とします。

外部向けAPIは提供せず、JinjaテンプレートによるHTML画面を基本とします。例外として、「ありがとう」の画面内更新にだけ同じPOSTルートのJSONレスポンスを使用します。

## 2. Blueprint構成

| Blueprint | 役割 | 主なエンドポイント |
| --- | --- | --- |
| `main` | アプリの入口 | `main.index` |
| `auth` | ユーザー登録と認証 | `auth.register`、`auth.login`、`auth.logout` |
| `activities` | 活動の一覧、作成、詳細、編集、削除、写真配信、リアクション | `activities.index`、`activities.create`、`activities.detail`、`activities.edit`、`activities.delete`、`activities.photo`、`activities.toggle_thank` |
| `users` | ログイン利用者のマイページ | `users.me` |

## 4. ルートごとの処理

### 4.1 トップ

**リクエスト**

- URL：`/`
- メソッド：GET
- エンドポイント：`main.index`
- ログイン：不要

**正常時**

- ログイン済みなら`activities.index`へ302リダイレクトする。
- 未ログインなら`auth.login`へ302リダイレクトする。
- データやセッションは変更しない。

**エラー時**

- ログイン状態の確認中に予期しない問題が起きた場合は500を返す。

### 4.2 ユーザー登録

**リクエスト**

- URL：`/register`
- メソッド：GET、POST
- エンドポイント：`auth.register`
- ログイン：不要
- テンプレート：`auth/register.html`

**GET**

- 未ログインなら空の登録フォームをHTTP 200で表示する。
- ログイン済みなら`activities.index`へ302リダイレクトする。
- データやセッションは変更しない。

**POST正常時**

1. CSRFトークンを検証する。
2. お名前、ログインID、パスワード、確認用パスワードを検証する。
3. パスワードをハッシュ化してユーザーを作成する。
4. 成功メッセージを設定する。
5. `auth.login`へ303リダイレクトする。

登録後に自動ログインは行いません。

**POSTエラー時**

- CSRFエラー：ユーザーを作成せず400を返す。
- 入力エラーまたはログインID重複：作成せず、HTTP 200で同じフォームを再表示する。
- パスワードと確認用パスワードは再表示しない。
- DB障害：処理を取り消して500を返す。

### 4.3 ログイン

**リクエスト**

- URL：`/login`
- メソッド：GET、POST
- エンドポイント：`auth.login`
- ログイン：不要
- テンプレート：`auth/login.html`

**GET**

- 未ログインなら空のログインフォームをHTTP 200で表示する。
- ログイン済みなら`activities.index`へ302リダイレクトする。
- セッションは変更しない。

**POST正常時**

1. CSRFトークンを検証する。
2. ログインIDとパスワードを検証する。
3. 認証に成功した利用者でログイン状態を開始する。
4. `activities.index`へ303リダイレクトする。

**POSTエラー時**

- CSRFエラー：セッションを変更せず400を返す。
- 認証失敗：セッションを変更せず、HTTP 200で同じフォームを再表示する。
- 認証失敗時は「ログインIDまたはパスワードが正しくありません」とだけ表示する。
- DB障害：500を返す。

### 4.4 ログアウト

**リクエスト**

- URL：`/logout`
- メソッド：POSTのみ
- エンドポイント：`auth.logout`
- ログイン：必要
- テンプレート：なし

**正常時**

1. CSRFトークンを検証する。
2. ログイン状態を終了する。
3. 成功メッセージを設定する。
4. `auth.login`へ303リダイレクトする。

**エラー時**

- GETなど許可していないメソッドには405を返し、ログイン状態を変更しない。
- CSRFエラーではログイン状態を変更せず400を返す。
- 未ログイン時はログイン画面へリダイレクトする。

### 4.5 みんなの活動一覧

**リクエスト**

- URL：`/activities?page=N`
- メソッド：GET
- エンドポイント：`activities.index`
- ログイン：必要
- テンプレート：`activities/index.html`

**正常時**

- 全活動の回数、所要時間、袋数を`COUNT`、`SUM`、`COALESCE`で集計する。
- 集計は全期間・全利用者を対象とし、一覧のページ番号では絞り込まない。
- `page`の省略時は1として扱う。
- 活動を作成日時の降順、同時刻の場合はIDの降順で取得する。
- 1ページにつき10件表示する。
- 前後ページの有無をテンプレートへ渡す。
- 活動が0件の場合も`page=1`はHTTP 200で表示する。
- 読み取りだけを行い、データは変更しない。

**エラー時**

- 未ログイン時は案内メッセージを付けて`auth.login`へ302リダイレクトする。
- `page`が整数でない、1未満、または存在する最終ページを超える場合は404を返す。
- DB障害は500を返す。

### 4.6 活動記録の作成

**リクエスト**

- URL：`/activities/new`
- メソッド：GET、POST
- エンドポイント：`activities.create`
- ログイン：必要
- テンプレート：`activities/create.html`

**GET**

- 活動日の初期値を当日にした空のフォームをHTTP 200で表示する。
- ルートが空の場合だけ、ブラウザー側で1回の現在地取得を開始できるボタンを表示する。ページ表示だけでは取得を開始しない。
- データは変更しない。

**POST正常時**

1. CSRFトークンを検証する。
2. 活動日、場所、所要時間、袋数、ゴミの種類、コメント、任意写真、任意の清掃ルートを検証する。
3. 写真がある場合は、向き補正、縮小、メタデータ除去を行う。HEIC・HEIFは先頭画像をJPEGまたはPNGへ変換し、ランダムな名前で保存する。
4. ログイン中の利用者を投稿者として活動、ゴミ種類、写真情報、清掃ルートを一括保存する。
5. 成功メッセージを設定する。
6. 作成した活動の`activities.detail`へ303リダイレクトする。

**POSTエラー時**

- CSRFエラー：保存せず400を返す。
- 入力エラー：保存せず、HTTP 200で入力値、見出し直後の全エラー概要、項目別エラーを含むフォームを再表示する。
- 写真が10MBを超える場合：保存せず、フォームで検出できた場合はHTTP 200、リクエスト全体の上限を超えた場合は413を返す。
- 写真保存またはDB保存の失敗：DB変更を取り消し、作成途中の画像を削除して500を返す。
- 清掃ルートが不正なJSON、1～100地点の範囲外、数値以外、緯度・経度の範囲外の場合：保存せずHTTP 200でフォームを再表示する。2地点以上が丸め後に同一点だけになる場合も拒否する。
- DB障害：処理を取り消して500を返す。
- 未ログイン時は保存せず、ログイン画面へリダイレクトする。
- 現在地の許可拒否、非対応、取得不能、10秒のタイムアウトはサーバーエラーにせず、手動入力を案内する。

### 4.7 活動詳細

**リクエスト**

- URL：`/activities/<int:activity_id>`
- メソッド：GET
- エンドポイント：`activities.detail`
- ログイン：必要
- テンプレート：`activities/detail.html`

**正常時**

- 指定IDの活動と投稿者を取得し、HTTP 200で表示する。
- 写真がある場合は、`activities.photo`を参照する画像を詳細画面だけに表示する。
- 清掃地点・ルートがある場合は、端点を丸めた保存済み座標をOpenStreetMap上へ表示する。1地点ではマーカーだけ、2地点以上では線と地点を表示する。
- 「ありがとう」の合計件数を表示し、他人の活動ではログイン利用者の送信状態に応じた送信・取消フォームを表示する。
- 読み取りだけを行い、データは変更しない。

**エラー時**

- 未ログイン時は`auth.login`へ302リダイレクトする。
- 指定IDの活動が存在しない場合は404を返す。
- DB障害は500を返す。

### 4.8 活動記録の編集

**リクエスト**

- URL：`/activities/<int:activity_id>/edit`
- メソッド：GET、POST
- エンドポイント：`activities.edit`
- ログイン：必要・投稿者本人限定
- テンプレート：`activities/edit.html`

**GET**

- 対象活動が存在し、ログイン中の利用者の投稿であることを確認する。存在しない場合または本人でない場合は404を返す。
- 指定活動の活動日、場所、所要時間、袋数、ゴミの種類、コメントを初期値として表示する。
- 既存写真がある場合は、現在の写真と「写真を削除する」選択肢を表示する。
- 既存ルートがある場合は編集用地図へ初期表示する。ルートを変更しないGETではデータを変更しない。
- 既存ルートがない場合だけ現在地ボタンを表示し、ルートをクリアした場合は再表示する。
- データやファイルは変更しない。

**POST正常時**

1. CSRFトークンを検証する。
2. 対象活動がログイン中の利用者の投稿であることを確認する。
3. 作成フォームと同じ規則で活動内容、任意の新しい写真、任意の清掃ルートを検証する。
4. 活動本体、ゴミ種類、清掃ルートを更新し、`updated_at`へUTCの現在日時を設定する。
5. 写真未選択なら既存写真を維持し、新規選択なら差し替え、削除指定なら写真情報を削除する。
6. 成功メッセージを設定し、対象の`activities.detail`へ303リダイレクトする。

**POSTエラー時**

- 対象活動が存在しない場合、または投稿者本人でない場合は404を返し、データを変更しない。
- CSRFエラー：更新せず400を返す。
- 入力エラー：更新せず、HTTP 200で入力値、見出し直後の全エラー概要、項目別エラーを含むフォームを再表示する。
- 新しい写真の選択と写真削除を同時に指定した場合は入力エラーとして扱う。
- 写真が10MBを超える場合：更新せず、フォームで検出できた場合はHTTP 200、リクエスト全体の上限を超えた場合は413を返す。
- 写真またはDBの更新に失敗した場合はDB変更を取り消し、新しく作成した画像を削除して既存写真を維持したうえで500を返す。

### 4.9 活動記録の削除

**リクエスト**

- URL：`/activities/<int:activity_id>/delete`
- メソッド：GET、POST
- エンドポイント：`activities.delete`
- ログイン：必要・投稿者本人限定
- テンプレート：`activities/delete.html`

**GET**

- 対象活動が存在し、ログイン中の利用者の投稿であることを確認する。存在しない場合または本人でない場合は404を返す。
- 活動日、場所、写真の有無と、削除後は元に戻せないことを表示する。
- データやファイルは変更しない。

**POST正常時**

1. CSRFトークンを検証する。
2. 対象活動がログイン中の利用者の投稿であることを再確認する。
3. 写真がある場合は、画像実体を後で削除するため写真情報を取得する。
4. トランザクション内で活動を完全削除し、関連するゴミ種類、写真情報、清掃ルートを`ON DELETE CASCADE`で削除する。
5. DB削除成功後、写真がある場合は画像実体を削除する。
6. 成功メッセージを設定し、`users.me`へ303リダイレクトする。

**POSTエラー時**

- 対象活動が存在しない場合、または投稿者本人でない場合は404を返し、データを変更しない。
- CSRFエラー：削除せず400を返す。
- DB削除に失敗した場合は処理を取り消して500を返し、画像実体を維持する。
- DB削除後に画像実体の削除だけ失敗した場合は活動削除を成功扱いとし、秘密情報や保存名を含めずログへ記録する。

### 4.10 活動写真

**リクエスト**

- URL：`/activities/<int:activity_id>/photo`
- メソッド：GET
- エンドポイント：`activities.photo`
- ログイン：必要
- テンプレート：なし

**正常時**

- 指定活動に関連する保存済み画像を、DBに記録したMIMEタイプで返す。
- 読み取りだけを行い、DBやファイルを変更しない。

**エラー時**

- 未ログイン時は`auth.login`へ302リダイレクトする。
- 写真情報または画像実体が存在しない場合は404を返す。

### 4.11 「ありがとう」の送信・取消

**リクエスト**

- URL：`/activities/<int:activity_id>/thanks`
- メソッド：POST
- エンドポイント：`activities.toggle_thank`
- ログイン：必要・他人の活動限定
- テンプレート：なし

**正常時**

1. CSRFトークンを検証する。
2. 対象活動が存在し、投稿者がログイン利用者本人ではないことをサーバー側で確認する。
3. 未送信ならリアクションを1件作成し、送信済みならログイン利用者自身のリアクションを削除する。
4. JSONを希望するリクエストには、更新後の件数、ログイン利用者の送信状態、成功メッセージを200で返す。この場合はフラッシュを保存しない。
5. 通常のフォーム送信には成功メッセージを設定し、対象の`activities.detail`へ303リダイレクトする。

**エラー時**

- 未ログイン時は`auth.login`へ302リダイレクトし、データを変更しない。
- GETなどPOST以外のメソッドは405を返す。
- CSRFエラーまたは本人の活動への送信は400を返し、データを変更しない。
- 指定活動が存在しない場合は404を返す。
- DB障害は変更を取り消して500を返す。

### 4.12 マイページ

**リクエスト**

- URL：`/me?page=N`
- メソッド：GET
- エンドポイント：`users.me`
- ログイン：必要
- テンプレート：`users/me.html`

**正常時**

- ログイン中の利用者の活動回数、累計活動時間、累計袋数を取得する。
- 同じ利用者の活動を作成日時の降順、同時刻の場合はIDの降順で取得する。
- 1ページにつき10件表示する。
- 活動が0件の場合も`page=1`はHTTP 200で表示し、集計値は0とする。
- 読み取りだけを行い、データは変更しない。

**エラー時**

- 未ログイン時は`auth.login`へ302リダイレクトする。
- `page`が整数でない、1未満、または存在する最終ページを超える場合は404を返す。
- DB障害は500を返す。

## 5. フォーム入力規則

### 5.1 ユーザー登録フォーム

| 項目 | 必須 | 規則 |
| --- | --- | --- |
| ログインID | 必須 | 3～30文字、重複不可 |
| お名前 | 必須 | 1～50文字 |
| パスワード | 必須 | 8～128文字 |
| パスワード（確認） | 必須 | パスワードと一致すること |

### 5.2 ログインフォーム

| 項目 | 必須 | 規則 |
| --- | --- | --- |
| ログインID | 必須 | 登録済みのログインIDと照合する |
| パスワード | 必須 | 保存済みのハッシュと安全に照合する |

### 5.3 活動記録フォーム

| 項目 | 必須 | 規則 |
| --- | --- | --- |
| 活動日 | 必須 | 正しい日付で、当日以前 |
| 活動場所 | 必須 | 1～100文字 |
| 所要時間 | 必須 | 1～1440分の整数 |
| 袋数 | 必須 | 0～99の整数 |
| ゴミの種類 | 必須 | 定義済みの4候補から一つ以上 |
| コメント | 任意 | 500文字以内 |
| 活動写真 | 任意 | 1枚、10MB以内、JPEG・PNG・WebP・HEIC・HEIF。拡張子と実内容が一致すること |
| 清掃ルート | 任意 | JSON配列の1～100地点。各地点は有効な緯度・経度で、1地点または始点・終点は保存前に小数点以下3桁へ丸める。2地点以上は丸め後も異なる地点を2つ以上含む |

前後の空白を除去した結果が空になる文字列は、必須項目では未入力として扱います。入力エラー時はHTTP 200で同じフォームを表示し、データを変更しません。

### 5.4 活動編集フォーム

- 活動内容と新しい写真には、活動記録フォームと同じ入力規則を適用する。
- 清掃ルートは変更しなければ維持し、空にして送信した場合は既存ルートを削除する。
- 写真が未選択で削除指定もない場合は、既存写真を維持する。
- 既存写真がある場合だけ写真削除を選択できる。
- 新しい写真の選択と写真削除は同時に指定できない。

### 5.5 活動削除確認フォーム

- 入力項目は設けず、CSRFトークンと「削除する」送信ボタンだけを持つ。
- 文字入力、チェックボックス、パスワード再入力は要求しない。

### 5.6 「ありがとう」フォーム

- CSRFトークンと送信ボタンだけを持つ。
- 活動IDや利用者IDをフォーム値として信用せず、URLとログイン状態からサーバー側で決定する。

## 6. 認証とアクセス制御

- `activities.index`、`activities.create`、`activities.detail`、`activities.edit`、`activities.delete`、`activities.photo`、`activities.toggle_thank`、`users.me`、`auth.logout`はログイン必須とする。
- 未ログインで保護ルートへアクセスした場合は、案内メッセージを付けて`auth.login`へ302リダイレクトする。
- 初版ではログイン後の戻り先指定を使用せず、常に`activities.index`へ移動する。
- 登録・ログイン画面へログイン済みでアクセスした場合も`activities.index`へ移動する。
- 活動情報は登録ユーザーだけが閲覧できる。
- `activities.edit`は投稿者本人だけに許可し、他人の活動IDを指定した場合は404を返す。
- `activities.delete`も投稿者本人だけに許可し、他人の活動IDを指定した場合は404を返す。
- `activities.toggle_thank`は他人の活動だけに許可し、本人の活動を指定した場合は400を返す。

## 7. HTTPメソッドとリダイレクト

- GETは画面表示とデータ取得だけに使用し、DBやセッションを変更しない。
- ユーザー登録、ログイン、活動作成、活動編集、活動削除、「ありがとう」の送信・取消、ログアウトはPOSTだけで状態を変更する。
- すべてのPOSTフォームをCSRF保護する。
- POST成功後は原則として303 See OtherでGETルートへリダイレクトする。「ありがとう」の画面内更新を希望するリクエストだけは200のJSONを返す。
- 通常の画面振り分けと未認証時の案内には302 Foundを使用する。
- 許可していないHTTPメソッドには405 Method Not Allowedを返す。

## 8. エラー処理

| 状態 | HTTPステータス | テンプレートまたは動作 |
| --- | --- | --- |
| フォーム入力エラー | 200 | 入力したフォームをエラー付きで再表示 |
| 未ログイン | 302 | `auth.login`へリダイレクト |
| CSRFエラー・不正なリクエスト | 400 | `errors/400.html` |
| 存在しない対象・ページ番号・他人の活動編集または削除 | 404 | `errors/404.html` |
| 許可されていないメソッド | 405 | Flaskの405応答。状態は変更しない |
| リクエスト容量超過 | 413 | `errors/413.html` |
| 予期しないサーバー・DB障害 | 500 | `errors/500.html` |

- エラー画面に例外、SQL、ファイルパス、秘密情報を表示しない。
- DBへの書き込み中に失敗した場合は処理を取り消す。
- エラーログには調査に必要な情報を残すが、パスワードを記録しない。
