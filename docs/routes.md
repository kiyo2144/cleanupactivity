# ひろまち ルーティング設計書

## 1. この文書について

この文書は、「ひろまち」初版（MVP）のFlaskルート、HTTPメソッド、認証、正常時とエラー時の処理を定めるものです。画面の表示内容は`docs/screens.md`、機能要件は`docs/requirements.md`を基準とします。

APIやJSONレスポンスは提供せず、JinjaテンプレートによるHTML画面を対象とします。

## 2. Blueprint構成

| Blueprint | 役割 | 主なエンドポイント |
| --- | --- | --- |
| `main` | アプリの入口 | `main.index` |
| `auth` | ユーザー登録と認証 | `auth.register`、`auth.login`、`auth.logout` |
| `activities` | 活動の一覧、作成、詳細、写真配信 | `activities.index`、`activities.create`、`activities.detail`、`activities.photo` |
| `users` | ログイン利用者のマイページ | `users.me` |

## 3. ルート一覧

| URL | HTTPメソッド | エンドポイント | ログイン | テンプレート | 役割 |
| --- | --- | --- | --- | --- | --- |
| `/` | GET | `main.index` | 不要 | なし | ログイン状態に応じて入口を振り分ける |
| `/register` | GET, POST | `auth.register` | 不要 | `auth/register.html` | ユーザー登録フォームの表示と登録 |
| `/login` | GET, POST | `auth.login` | 不要 | `auth/login.html` | ログインフォームの表示と認証 |
| `/logout` | POST | `auth.logout` | 必要 | なし | ログアウト |
| `/activities` | GET | `activities.index` | 必要 | `activities/index.html` | 全利用者の活動一覧 |
| `/activities/new` | GET, POST | `activities.create` | 必要 | `activities/create.html` | 活動記録フォームの表示と登録 |
| `/activities/<int:activity_id>` | GET | `activities.detail` | 必要 | `activities/detail.html` | 活動詳細 |
| `/activities/<int:activity_id>/photo` | GET | `activities.photo` | 必要 | なし | 活動写真の配信 |
| `/me` | GET | `users.me` | 必要 | `users/me.html` | 自分の集計と活動一覧 |

活動の編集・削除用ルートは定義しません。

## 4. ルートごとの処理

### 4.1 トップ

**リクエスト**

- URL：`/`
- メソッド：GET
- エンドポイント：`main.index`
- ログイン：不要

**正常時**

- ログイン済みなら`activities.index`へ302リダイレクトする。
- 未ログインなら`auth.login`へ302リダイレクトする。
- データやセッションは変更しない。

**エラー時**

- ログイン状態の確認中に予期しない問題が起きた場合は500を返す。

### 4.2 ユーザー登録

**リクエスト**

- URL：`/register`
- メソッド：GET、POST
- エンドポイント：`auth.register`
- ログイン：不要
- テンプレート：`auth/register.html`

**GET**

- 未ログインなら空の登録フォームをHTTP 200で表示する。
- ログイン済みなら`activities.index`へ302リダイレクトする。
- データやセッションは変更しない。

**POST正常時**

1. CSRFトークンを検証する。
2. ユーザーID、お名前、パスワード、確認用パスワードを検証する。
3. パスワードをハッシュ化してユーザーを作成する。
4. 成功メッセージを設定する。
5. `auth.login`へ303リダイレクトする。

登録後に自動ログインは行いません。

**POSTエラー時**

- CSRFエラー：ユーザーを作成せず400を返す。
- 入力エラーまたはユーザーID重複：作成せず、HTTP 200で同じフォームを再表示する。
- パスワードと確認用パスワードは再表示しない。
- DB障害：処理を取り消して500を返す。

### 4.3 ログイン

**リクエスト**

- URL：`/login`
- メソッド：GET、POST
- エンドポイント：`auth.login`
- ログイン：不要
- テンプレート：`auth/login.html`

**GET**

- 未ログインなら空のログインフォームをHTTP 200で表示する。
- ログイン済みなら`activities.index`へ302リダイレクトする。
- セッションは変更しない。

**POST正常時**

1. CSRFトークンを検証する。
2. ユーザーIDとパスワードを検証する。
3. 認証に成功した利用者でログイン状態を開始する。
4. `activities.index`へ303リダイレクトする。

**POSTエラー時**

- CSRFエラー：セッションを変更せず400を返す。
- 認証失敗：セッションを変更せず、HTTP 200で同じフォームを再表示する。
- 認証失敗時は「ユーザーIDまたはパスワードが正しくありません」とだけ表示する。
- DB障害：500を返す。

### 4.4 ログアウト

**リクエスト**

- URL：`/logout`
- メソッド：POSTのみ
- エンドポイント：`auth.logout`
- ログイン：必要
- テンプレート：なし

**正常時**

1. CSRFトークンを検証する。
2. ログイン状態を終了する。
3. 成功メッセージを設定する。
4. `auth.login`へ303リダイレクトする。

**エラー時**

- GETなど許可していないメソッドには405を返し、ログイン状態を変更しない。
- CSRFエラーではログイン状態を変更せず400を返す。
- 未ログイン時はログイン画面へリダイレクトする。

### 4.5 みんなの活動一覧

**リクエスト**

- URL：`/activities?page=N`
- メソッド：GET
- エンドポイント：`activities.index`
- ログイン：必要
- テンプレート：`activities/index.html`

**正常時**

- `page`の省略時は1として扱う。
- 活動を作成日時の降順、同時刻の場合はIDの降順で取得する。
- 1ページにつき10件表示する。
- 前後ページの有無をテンプレートへ渡す。
- 活動が0件の場合も`page=1`はHTTP 200で表示する。
- 読み取りだけを行い、データは変更しない。

**エラー時**

- 未ログイン時は案内メッセージを付けて`auth.login`へ302リダイレクトする。
- `page`が整数でない、1未満、または存在する最終ページを超える場合は404を返す。
- DB障害は500を返す。

### 4.6 活動記録の作成

**リクエスト**

- URL：`/activities/new`
- メソッド：GET、POST
- エンドポイント：`activities.create`
- ログイン：必要
- テンプレート：`activities/create.html`

**GET**

- 活動日の初期値を当日にした空のフォームをHTTP 200で表示する。
- データは変更しない。

**POST正常時**

1. CSRFトークンを検証する。
2. 活動日、場所、所要時間、袋数、ゴミの種類、コメント、任意写真を検証する。
3. 写真がある場合は、向き補正、縮小、メタデータ除去を行い、ランダムな名前で保存する。
4. ログイン中の利用者を投稿者として活動、ゴミ種類、写真情報を一括保存する。
5. 成功メッセージを設定する。
6. 作成した活動の`activities.detail`へ303リダイレクトする。

**POSTエラー時**

- CSRFエラー：保存せず400を返す。
- 入力エラー：保存せず、HTTP 200で入力値とエラーを含むフォームを再表示する。
- 写真が5MBを超える場合：保存せず、フォームで検出できた場合はHTTP 200、リクエスト全体の上限を超えた場合は413を返す。
- 写真保存またはDB保存の失敗：DB変更を取り消し、作成途中の画像を削除して500を返す。
- DB障害：処理を取り消して500を返す。
- 未ログイン時は保存せず、ログイン画面へリダイレクトする。

### 4.7 活動詳細

**リクエスト**

- URL：`/activities/<int:activity_id>`
- メソッド：GET
- エンドポイント：`activities.detail`
- ログイン：必要
- テンプレート：`activities/detail.html`

**正常時**

- 指定IDの活動と投稿者を取得し、HTTP 200で表示する。
- 写真がある場合は、`activities.photo`を参照する画像を詳細画面だけに表示する。
- 読み取りだけを行い、データは変更しない。

**エラー時**

- 未ログイン時は`auth.login`へ302リダイレクトする。
- 指定IDの活動が存在しない場合は404を返す。
- DB障害は500を返す。

### 4.8 活動写真

**リクエスト**

- URL：`/activities/<int:activity_id>/photo`
- メソッド：GET
- エンドポイント：`activities.photo`
- ログイン：必要
- テンプレート：なし

**正常時**

- 指定活動に関連する保存済み画像を、DBに記録したMIMEタイプで返す。
- 読み取りだけを行い、DBやファイルを変更しない。

**エラー時**

- 未ログイン時は`auth.login`へ302リダイレクトする。
- 写真情報または画像実体が存在しない場合は404を返す。

### 4.9 マイページ

**リクエスト**

- URL：`/me?page=N`
- メソッド：GET
- エンドポイント：`users.me`
- ログイン：必要
- テンプレート：`users/me.html`

**正常時**

- ログイン中の利用者の活動回数、累計活動時間、累計袋数を取得する。
- 同じ利用者の活動を作成日時の降順、同時刻の場合はIDの降順で取得する。
- 1ページにつき10件表示する。
- 活動が0件の場合も`page=1`はHTTP 200で表示し、集計値は0とする。
- 読み取りだけを行い、データは変更しない。

**エラー時**

- 未ログイン時は`auth.login`へ302リダイレクトする。
- `page`が整数でない、1未満、または存在する最終ページを超える場合は404を返す。
- DB障害は500を返す。

## 5. フォーム入力規則

### 5.1 ユーザー登録フォーム

| 項目 | 必須 | 規則 |
| --- | --- | --- |
| ユーザーID | 必須 | 3～30文字、重複不可 |
| お名前 | 必須 | 1～50文字 |
| パスワード | 必須 | 8～128文字 |
| パスワード（確認） | 必須 | パスワードと一致すること |

### 5.2 ログインフォーム

| 項目 | 必須 | 規則 |
| --- | --- | --- |
| ユーザーID | 必須 | 登録済みのユーザーIDと照合する |
| パスワード | 必須 | 保存済みのハッシュと安全に照合する |

### 5.3 活動記録フォーム

| 項目 | 必須 | 規則 |
| --- | --- | --- |
| 活動日 | 必須 | 正しい日付で、当日以前 |
| 活動場所 | 必須 | 1～100文字 |
| 所要時間 | 必須 | 1～1440分の整数 |
| 袋数 | 必須 | 0～99の整数 |
| ゴミの種類 | 必須 | 定義済みの4候補から一つ以上 |
| コメント | 任意 | 500文字以内 |
| 活動写真 | 任意 | 1枚、5MB以内、JPEG・PNG・WebP。拡張子と実内容が一致すること |

前後の空白を除去した結果が空になる文字列は、必須項目では未入力として扱います。入力エラー時はHTTP 200で同じフォームを表示し、データを変更しません。

## 6. 認証とアクセス制御

- `activities.index`、`activities.create`、`activities.detail`、`activities.photo`、`users.me`、`auth.logout`はログイン必須とする。
- 未ログインで保護ルートへアクセスした場合は、案内メッセージを付けて`auth.login`へ302リダイレクトする。
- 初版ではログイン後の戻り先指定を使用せず、常に`activities.index`へ移動する。
- 登録・ログイン画面へログイン済みでアクセスした場合も`activities.index`へ移動する。
- 活動情報は登録ユーザーだけが閲覧できる。
- 初版では更新・削除ルートを設けないため、活動の所有者による変更操作も提供しない。

## 7. HTTPメソッドとリダイレクト

- GETは画面表示とデータ取得だけに使用し、DBやセッションを変更しない。
- ユーザー登録、ログイン、活動作成、ログアウトはPOSTだけで状態を変更する。
- すべてのPOSTフォームをCSRF保護する。
- POST成功後は303 See OtherでGETルートへリダイレクトする。
- 通常の画面振り分けと未認証時の案内には302 Foundを使用する。
- 許可していないHTTPメソッドには405 Method Not Allowedを返す。

## 8. エラー処理

| 状態 | HTTPステータス | テンプレートまたは動作 |
| --- | --- | --- |
| フォーム入力エラー | 200 | 入力したフォームをエラー付きで再表示 |
| 未ログイン | 302 | `auth.login`へリダイレクト |
| CSRFエラー・不正なリクエスト | 400 | `errors/400.html` |
| 存在しない対象・ページ番号 | 404 | `errors/404.html` |
| 許可されていないメソッド | 405 | Flaskの405応答。状態は変更しない |
| リクエスト容量超過 | 413 | `errors/413.html` |
| 予期しないサーバー・DB障害 | 500 | `errors/500.html` |

- エラー画面に例外、SQL、ファイルパス、秘密情報を表示しない。
- DBへの書き込み中に失敗した場合は処理を取り消す。
- エラーログには調査に必要な情報を残すが、パスワードを記録しない。

## 10. 実装対象外

初版では、次のルートと処理を設けません。

- 活動記録の編集・削除
- ユーザープロフィールの編集
- ランキング、リアクション、コメント、フォロー
- メール認証、パスワード再設定
- JSON API
