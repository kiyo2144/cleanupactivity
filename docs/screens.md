# ひろまち 画面設計書

## 1. この文書について

この文書は、「ひろまち」初版（MVP）の画面構成、表示内容、操作、画面遷移を定めるものです。要件は `docs/requirements.md`、ルートの処理は `docs/routes.md`を基準とします。

活動写真は任意で1枚だけ扱い、投稿者本人による活動編集と完全削除、任意の清掃ルート、「ありがとう」を追加機能として設計します。削除後の復元、ランキング、「ありがとう」以外の交流機能は扱いません。画面はスマートフォンでの利用を優先します。

## 2. 共通レイアウト

| 項目 | 内容 |
| --- | --- |
| 目的 | 現在のログイン状態を示し、主要な画面へ迷わず移動できるようにする |
| ログイン | 不要。表示するナビゲーションはログイン状態で切り替える |
| URL・HTTPメソッド | 各画面のURLとメソッドに従う |
| Flaskエンドポイント | 各画面のエンドポイントに従う |
| テンプレート | `base.html` |

### 表示要素

- ヘッダーにアプリ名「ひろまち」を表示する。
- アプリ名は`main.index`へのリンクにする。
- 未ログイン時は「ログイン」「ユーザー登録」を表示する。
- ログイン中は「みんなの活動」「新しく記録する」「マイページ」を表示する。
- ログアウトはリンクではなく、CSRFトークンを含むPOSTフォームのボタンとして表示する。
- 成功、注意、エラーのフラッシュメッセージを本文の先頭に表示する。
- フォーム全体のエラーと項目別エラーを読み分けられる見た目にする。

### 正常時とエラー時の動作

- ナビゲーションを選ぶと、対応するGET画面へ移動する。
- ログアウトボタンを押すと、`POST /logout`を送信する。
- CSRF検証に失敗した場合は、ログアウトなどの処理を行わず400エラー画面を表示する。
- エラー画面でも、利用可能な戻り先を表示する。

### 簡易ワイヤーフレーム

```text
+----------------------------------+
| ひろまち                         |
| [みんなの活動] [記録] [マイページ]|
|                         [ログアウト]|
+----------------------------------+
| フラッシュメッセージ              |
+----------------------------------+
|                                  |
| 各画面の内容                      |
|                                  |
+----------------------------------+
```

スマートフォンでは、ナビゲーションを折り返して縦方向にも配置できるようにします。

## 3. ユーザー登録画面

| 項目 | 内容 |
| --- | --- |
| 目的 | 新しい利用者がアカウントを作成する |
| ログイン | 不要。ログイン済みの場合は活動一覧へ移動する |
| URL・HTTPメソッド | `GET /register`、`POST /register` |
| Flaskエンドポイント | `auth.register` |
| テンプレート | `auth/register.html` |

### 表示要素

- タイトル「ユーザー登録」
- お名前：1～50文字
- ログインID：3～30文字
- パスワード：8～128文字
- パスワード（確認）
- 「登録する」ボタン
- 「ログインはこちら」リンク
- ログインIDはログインに、お名前は活動画面での公開表示に使うことの説明
- 4つの入力項目に赤い`*`を付け、「* は必須項目です。」と表示

パスワード欄は入力内容を伏せて表示します。

### 正常時

- `GET`では空の登録フォームを表示する。
- `POST`の入力が有効ならユーザーを作成し、成功メッセージを付けてログイン画面へ303リダイレクトする。

### エラー時

- 必須項目、文字数、パスワード確認、ログインIDの重複を検証する。
- エラーがある場合はユーザーを作成せず、HTTP 200で同じ画面を再表示する。
- ログインIDとお名前は保持し、パスワード欄は空に戻す。
- DB障害などの予期しないエラーではユーザーを作成せず、500エラー画面を表示する。

### 画面遷移

- 登録成功 → ログイン画面
- 「ログインはこちら」 → ログイン画面
- 入力エラー → ユーザー登録画面

### 簡易ワイヤーフレーム

```text
+----------------------------+
| ユーザー登録               |
| * は必須項目です。        |
| お名前     * [____________]  |
| ログインID * [____________]  |
| パスワード * [____________]  |
| 確認用     * [____________]  |
| [登録する]                 |
| ログインはこちら           |
+----------------------------+
```

## 4. ログイン画面

| 項目 | 内容 |
| --- | --- |
| 目的 | 登録済み利用者を認証し、アプリを利用できる状態にする |
| ログイン | 不要。ログイン済みの場合は活動一覧へ移動する |
| URL・HTTPメソッド | `GET /login`、`POST /login` |
| Flaskエンドポイント | `auth.login` |
| テンプレート | `auth/login.html` |

### 表示要素

- タイトル「ログイン」
- ログインID
- パスワード
- 「ログインする」ボタン
- 「ユーザー登録はこちら」リンク

### 正常時

- `GET`では空のログインフォームを表示する。
- `POST`で認証に成功したらログイン状態を開始し、活動一覧へ303リダイレクトする。

- 認証に失敗した場合はログイン状態を変更しない。
- ログインIDとパスワードのどちらが誤っているか区別せず、「ログインIDまたはパスワードが正しくありません」と表示する。

### 画面遷移

- ログイン成功 → みんなの活動一覧
- 「ユーザー登録はこちら」 → ユーザー登録画面
- 認証失敗 → ログイン画面

### 簡易ワイヤーフレーム

```text
+----------------------------+
| ログイン                   |
| ログインID [____________]  |
| パスワード [____________]  |
| [ログインする]             |
| ユーザー登録はこちら       |
+----------------------------+
```

## 5. みんなの活動一覧画面

| 項目 | 内容 |
| --- | --- |
| 目的 | 登録利用者の清掃活動を共有し、地域の活動を見えるようにする |
| ログイン | 必要 |
| URL・HTTPメソッド | `GET /activities?page=N` |
| Flaskエンドポイント | `activities.index` |
| テンプレート | `activities/index.html` |

### 表示要素

- タイトル「みんなの活動」
- 「まちのみんなの成果」として全期間の活動回数、累計時間、累計袋数
- 「新しく記録する」ボタン
- 新しい順に並べた活動カード（1ページ10件）
- 各カードに活動日、投稿者のお名前、場所、所要時間、袋数、ゴミの種類を表示する。
- カード全体または「詳しく見る」リンクから活動詳細へ移動できるようにする。
- 2ページ以上ある場合は「前へ」「次へ」を表示する。移動先がないボタンは表示しない。

### 正常時

- 集計値はページ分割前の全活動を対象にし、活動の作成・編集・削除を次回表示時に反映する。
- 活動が0件の場合も3つの集計値を0で表示する。
- `page`が省略された場合は1ページ目を表示する。
- 活動が0件の場合は「まだ活動記録がありません」と「最初の活動を記録する」ボタンを表示する。

### エラー時

- 未ログインの場合は案内メッセージを付けてログイン画面へリダイレクトする。
- `page`が1未満、整数でない、または存在する最終ページを超える場合は404エラー画面を表示する。
- ただし活動が0件の場合の`page=1`は正常画面として扱う。
- DB障害などの予期しないエラーでは500エラー画面を表示する。

### 画面遷移

- 「新しく記録する」 → 活動記録作成画面
- 活動カード → 対応する活動詳細画面
- 「前へ」「次へ」 → 活動一覧の前後ページ
- ナビゲーション「マイページ」 → マイページ
- ログアウト → `POST /logout` → ログイン画面

### 簡易ワイヤーフレーム

```text
+--------------------------------+
| みんなの活動                   |
| [新しく記録する]               |
| +----------------------------+ |
| | 10/11 佐藤さん             | |
| | フットパス北側 / 30分       | |
| | 1袋 / 燃えるごみ            | |
| |                 詳しく見る | |
| +----------------------------+ |
| +----------------------------+ |
| | 次の活動カード             | |
| +----------------------------+ |
| [前へ]                  [次へ] |
+--------------------------------+
```

## 6. 活動記録作成画面

| 項目 | 内容 |
| --- | --- |
| 目的 | 清掃活動後に、活動内容と成果を短時間で記録する |
| ログイン | 必要 |
| URL・HTTPメソッド | `GET /activities/new`、`POST /activities/new` |
| Flaskエンドポイント | `activities.create` |
| テンプレート | `activities/create.html` |

### 表示要素

- タイトル「清掃活動の記録」
- 活動日：必須。今日以前の日付
- 活動場所：必須。1～100文字
- 清掃ルート：任意。地図を順番にタップして2～100地点を指定
- ルートが空の場合だけ表示する「現在地から始める」ボタン
- 現在地の取得中、取得精度、拒否・失敗を知らせる状態表示
- 所要時間（分）：必須。1～1440の整数
- ゴミの袋数：必須。0～99の整数
- ゴミの種類：必須。次から一つ以上を選択
  - 燃えるごみ
  - プラスチック・ペットボトル
  - 缶・びん
  - その他
- コメント・感想：任意。500文字以内
- 活動写真：任意。JPEG・PNG・WebP・HEIC・HEIF、10MB以内、1枚
- 写真選択後に縦横比を維持したプレビューと「選択を取り消す」ボタン
- 写真へ人物や個人情報を写さないよう促す注意書き
- 活動場所へ自宅の番地などを書かないよう促す注意書き
- ルートの始点・終点を約100m単位に丸めて保存する旨の注意書き
- 「1地点戻す」「ルートをクリア」ボタン
- 「記録する」ボタン
- 「キャンセル」リンク

写真のプレビューと清掃ルート入力地図を含め、すべての入力項目を1画面に配置します。「現在地から始める」は自動実行せず、押された場合だけ現在地を1回取得して始点にします。始点はドラッグして修正できます。地図や現在地を利用できない場合も手動入力またはルートなしで投稿できます。JPEG・PNG・WebPは最大高さ360pxで画像全体を表示します。HEIC・HEIFをブラウザーで表示できない場合は投稿後に変換される旨を案内し、JavaScriptが無効でも投稿できる構成にします。

### 正常時

- `GET`では空のフォームを表示し、活動日の初期値には当日を設定する。
- `POST`の入力が有効ならログイン中の利用者の活動として、任意の清掃ルートと一括保存する。
- 保存成功後、作成した活動詳細へ303リダイレクトし、成功メッセージを表示する。

### エラー時

- 必須項目、日付、文字数、数値範囲、ゴミの種類を検証する。
- 清掃ルートはJSON形式、2～100地点、緯度・経度の範囲をサーバー側で検証する。
- 写真はサーバー側で容量、拡張子、実内容を検証し、問題があれば活動を保存しない。
- ブラウザー側でも写真の形式と10MB上限を確認し、問題があれば選択直後に案内する。ただし、最終判定はサーバー側で行う。
- 現在地の許可拒否、非対応、取得不能、10秒のタイムアウトでは手動入力を案内し、フォームを使用不能にしない。
- エラーがある場合は保存せず、HTTP 200で入力内容を保持した同じ画面を再表示する。
- DB障害などの予期しないエラーでは保存処理を取り消し、500エラー画面を表示する。
- 未ログインの場合はログイン画面へリダイレクトする。

### 画面遷移

- 保存成功 → 作成した活動の詳細画面
- 「キャンセル」 → みんなの活動一覧
- 入力エラー → 活動記録作成画面

### 簡易ワイヤーフレーム

```text
+--------------------------------+
| 清掃活動の記録                 |
| 活動日        [____/__/__]      |
| 活動場所      [______________]  |
| 清掃ルート（任意）             |
| [現在地から始める]             |
| [地図：タップした地点を線で接続]|
| [1地点戻す] [ルートをクリア]   |
| 所要時間（分）[____]            |
| ゴミの袋数    [____]            |
| ゴミの種類                     |
| [ ] 燃えるごみ                  |
| [ ] プラスチック・ペットボトル  |
| [ ] 缶・びん  [ ] その他        |
| コメント                       |
| [____________________________]  |
| 活動写真（任意）[ファイル選択] |
| [選択した写真のプレビュー]     |
| [選択を取り消す]               |
| [記録する]  キャンセル          |
+--------------------------------+
```

## 7. 活動詳細画面

| 項目 | 内容 |
| --- | --- |
| 目的 | 一つの活動記録について詳しい内容を確認する |
| ログイン | 必要 |
| URL・HTTPメソッド | `GET /activities/<int:activity_id>` |
| Flaskエンドポイント | `activities.detail` |
| テンプレート | `activities/detail.html` |

### 表示要素

- タイトル「活動の詳細」
- 投稿者のお名前
- 活動日
- 活動場所
- 所要時間
- ゴミの袋数
- ゴミの種類
- コメント・感想
- 添付写真（登録されている場合だけ表示）
- 清掃ルート地図（登録されている場合だけ表示）
- 「ありがとう」の合計件数
- 他人の活動の場合は「ありがとうを送る」または「ありがとうを取り消す」ボタン
- 「みんなの活動へ戻る」リンク
- 自分の活動の場合は「マイページへ戻る」リンク
- 自分の活動の場合だけ「編集する」ボタン
- 自分の活動の場合だけ「削除する」ボタン

他人の活動には編集・削除ボタンを表示しません。自分の活動には「ありがとう」の操作ボタンを表示せず、合計件数だけを表示します。送信者のお名前は表示しません。

### 正常時

- URLで指定された活動を表示する。
- コメントが未入力の場合は「コメントなし」と表示する。
- 写真がある場合は認証が必要な専用URLから読み込み、ない場合は写真欄を表示しない。
- ルートがある場合は、始点・終点をぼかした線をOpenStreetMap上へ表示する。ルートがない場合は地図欄を表示しない。
- OpenStreetMapの帰属表示を地図上へ常時表示する。
- 他人の活動で「ありがとう」を送信または取り消すと、処理結果を表示して同じ詳細画面へ戻る。

### エラー時

- 指定された活動が存在しない場合は404エラー画面を表示する。
- 未ログインの場合はログイン画面へリダイレクトする。
- DB障害などの予期しないエラーでは500エラー画面を表示する。

### 画面遷移

- 「みんなの活動へ戻る」 → みんなの活動一覧
- 「マイページへ戻る」 → マイページ
- 「編集する」 → 活動編集画面
- 「削除する」 → 活動削除確認画面
- 「ありがとうを送る」「ありがとうを取り消す」 → `POST /activities/<int:activity_id>/thanks` → 同じ活動詳細
- ログアウト → `POST /logout` → ログイン画面

### 簡易ワイヤーフレーム

```text
+----------------------------+
| 活動の詳細                 |
| 投稿者：佐藤さん           |
| 活動日：2026/10/11         |
| 場所：フットパス北側       |
| 所要時間：30分             |
| 袋数：1袋                  |
| 種類：燃えるごみ           |
| コメント：道路脇を清掃した |
| [活動写真]                 |
| 清掃ルート                 |
| [地図：登録済みルート]     |
| ありがとう 2件             |
| [ありがとうを送る]         |
| [編集する]                 |
| [削除する]                 |
| [みんなの活動へ戻る]       |
+----------------------------+
```

## 8. 活動編集画面

| 項目 | 内容 |
| --- | --- |
| 目的 | 投稿者本人が自分の活動内容と写真を修正する |
| ログイン | 必要。投稿者本人だけ利用可能 |
| URL・HTTPメソッド | `GET /activities/<int:activity_id>/edit`、`POST /activities/<int:activity_id>/edit` |
| Flaskエンドポイント | `activities.edit` |
| テンプレート | `activities/edit.html` |

### 表示要素

- タイトル「活動を編集」
- 活動日、活動場所、所要時間、袋数、ゴミの種類、コメント・感想
- 既存写真（登録されている場合）
- 既存の清掃ルート（登録されている場合）
- 清掃ルートの修正・解除に使う地図と操作ボタン
- 既存ルートがない場合だけ表示する「現在地から始める」ボタン
- 任意の新しい写真と投稿前プレビュー
- 既存写真がある場合だけ「写真を削除する」選択肢
- 「更新する」ボタン
- 「キャンセル」リンク

GET時は現在の活動内容と清掃ルートを初期値として表示します。写真を選ばず、写真削除も選ばなければ既存写真を維持します。ルートを変更しなければ既存ルートを維持し、地図上でクリアした場合はルートだけを削除します。ルートをクリアすると現在地ボタンを再表示します。

### 正常時

- 投稿者本人が有効な内容をPOSTすると、活動、ゴミ種類、写真情報、清掃ルートを一括更新する。
- 新しい写真を選んだ場合は既存写真を差し替え、写真削除を選んだ場合は写真だけを削除する。
- `updated_at`をUTCで更新するが、更新日時は画面に表示しない。
- 更新後は活動詳細画面へ303リダイレクトする。

### エラー時

- 未ログインの場合はログイン画面へリダイレクトする。
- 活動が存在しない場合、または他人の活動の場合は404エラー画面を表示する。
- 入力エラーではデータと既存写真を変更せず、HTTP 200で入力値とエラーを含む画面を再表示する。
- 新しい写真の選択と写真削除を同時に指定した場合は、どちらか一方を選ぶよう案内する。
- 写真やDBの更新に失敗した場合は変更を取り消し、新しく作成した画像を後片付けして500エラー画面を表示する。

### 画面遷移

- 「更新する」 → 更新した活動の詳細画面
- 「キャンセル」 → 編集対象の活動詳細画面
- 入力エラー → 入力内容を保持して活動編集画面を再表示

### 簡易ワイヤーフレーム

```text
+--------------------------------+
| 活動を編集                     |
| 活動日       [2026-10-11]      |
| 場所         [______________]  |
| 清掃ルート   [編集用の地図]   |
|              [現在地から始める]|
| [1地点戻す] [ルートをクリア]  |
| 所要時間     [30] 分           |
| 袋数         [1] 袋            |
| ゴミの種類   [x] 燃えるごみ   |
| コメント     [______________]  |
| 現在の写真   [活動写真]        |
| 新しい写真   [ファイル選択]    |
| [ ] 写真を削除する             |
| [更新する]  キャンセル         |
+--------------------------------+
```

## 9. 活動削除確認画面

| 項目 | 内容 |
| --- | --- |
| 目的 | 投稿者本人が削除対象を確認し、活動を完全削除する |
| ログイン | 必要。投稿者本人だけ利用可能 |
| URL・HTTPメソッド | `GET /activities/<int:activity_id>/delete`、`POST /activities/<int:activity_id>/delete` |
| Flaskエンドポイント | `activities.delete` |
| テンプレート | `activities/delete.html` |

### 表示要素

- タイトル「活動を削除」
- 対象の活動日と活動場所
- 写真が登録されているかどうか
- 「削除すると元に戻せません」という注意
- 「削除する」POSTボタン
- 「キャンセル」リンク

文字入力、確認チェック、パスワード再入力は求めません。

### 正常時

- GETでは確認内容だけを表示し、DBや画像実体を変更しない。
- POSTでは投稿者本人であることを再確認し、活動、ゴミ種類、写真情報を完全削除する。
- DB削除成功後に写真実体を削除する。
- 削除成功後は成功メッセージを表示し、マイページへ303リダイレクトする。

### エラー時

- 未ログインの場合はログイン画面へリダイレクトする。
- 活動が存在しない場合、または他人の活動の場合は404エラー画面を表示する。
- CSRFエラーでは削除せず400エラー画面を表示する。
- DB削除に失敗した場合は変更を取り消し、写真実体を維持して500エラー画面を表示する。
- DB削除後に写真実体だけ削除できない場合は削除成功として扱い、安全な内容でログへ記録する。

### 画面遷移

- 「削除する」 → マイページ
- 「キャンセル」 → 削除対象の活動詳細画面

### 簡易ワイヤーフレーム

```text
+--------------------------------+
| 活動を削除                     |
| この操作は元に戻せません。     |
| 活動日：2026/10/11             |
| 場所：フットパス北側           |
| 写真：あり                     |
| [削除する]  キャンセル         |
+--------------------------------+
```

## 10. マイページ

| 項目 | 内容 |
| --- | --- |
| 目的 | 自分の活動と累計成果を振り返る |
| ログイン | 必要 |
| URL・HTTPメソッド | `GET /me?page=N` |
| Flaskエンドポイント | `users.me` |
| テンプレート | `users/me.html` |

### 表示要素

- タイトル「マイページ」
- 自分のお名前
- 活動回数
- 累計活動時間
- 累計袋数
- 「新しく記録する」ボタン
- 自分の活動を新しい順に並べた活動カード（1ページ10件）
- 必要な場合だけ「前へ」「次へ」を表示する。

### 正常時

- ログイン中の利用者の集計と活動だけを表示する。
- 自分の活動が0件の場合は、累計を0として「最初の活動を記録する」ボタンを表示する。

### エラー時

- 未ログインの場合はログイン画面へリダイレクトする。
- `page`が1未満、整数でない、または存在する最終ページを超える場合は404エラー画面を表示する。
- ただし自分の活動が0件の場合の`page=1`は正常画面として扱う。
- DB障害などの予期しないエラーでは500エラー画面を表示する。

### 画面遷移

- 「新しく記録する」 → 活動記録作成画面
- 活動カード → 対応する活動詳細画面
- 「前へ」「次へ」 → マイページの前後ページ
- ナビゲーション「みんなの活動」 → みんなの活動一覧
- ログアウト → `POST /logout` → ログイン画面

### 簡易ワイヤーフレーム

```text
+--------------------------------+
| マイページ                     |
| 佐藤さん                       |
| 活動 5回 / 合計 180分 / 6袋    |
| [新しく記録する]               |
| +----------------------------+ |
| | 10/11 フットパス北側       | |
| | 30分 / 1袋      詳しく見る | |
| +----------------------------+ |
| [前へ]                  [次へ] |
+--------------------------------+
```

## 11. エラー画面

### 11.1 400 Bad Request

| 項目 | 内容 |
| --- | --- |
| 目的 | CSRFエラーなど、受け付けられないリクエストであることを知らせる |
| ログイン | 不要 |
| URL・HTTPメソッド | エラーが発生したURLとメソッド |
| Flaskエンドポイント | 400エラーハンドラー |
| テンプレート | `errors/400.html` |

- 「リクエストを処理できませんでした」と、再操作を促す案内を表示する。
- データやログイン状態は変更しない。
- ログイン中は活動一覧、未ログイン時はログイン画面へのリンクを表示する。

### 11.2 404 Not Found

| 項目 | 内容 |
| --- | --- |
| 目的 | 指定したページ、活動、一覧ページが存在しないことを知らせる |
| ログイン | 不要 |
| URL・HTTPメソッド | 存在しないURL、または存在しない対象を指定したGET |
| Flaskエンドポイント | 404エラーハンドラー |
| テンプレート | `errors/404.html` |

- 「ページが見つかりません」と表示する。
- ログイン中は活動一覧、未ログイン時はログイン画面へのリンクを表示する。

### 11.3 413 Payload Too Large

| 項目 | 内容 |
| --- | --- |
| 目的 | 送信データが容量上限を超えたことを知らせる |
| ログイン | 不要 |
| URL・HTTPメソッド | 容量超過が発生したURLとメソッド |
| Flaskエンドポイント | 413エラーハンドラー |
| テンプレート | `errors/413.html` |

- 写真は10MB以内で選び直すよう案内する。
- DBとファイルを変更せず、送信元が作成または編集画面の場合は対応する画面へ戻るリンクを表示する。

### 11.4 500 Internal Server Error

| 項目 | 内容 |
| --- | --- |
| 目的 | 予期しない障害が発生し、処理を完了できなかったことを知らせる |
| ログイン | 不要 |
| URL・HTTPメソッド | エラーが発生したURLとメソッド |
| Flaskエンドポイント | 500エラーハンドラー |
| テンプレート | `errors/500.html` |

- 「処理中にエラーが発生しました」と表示し、内部情報や例外内容は表示しない。
- 更新処理中だった場合は中途半端な変更を残さない。
- ログイン中は活動一覧、未ログイン時はログイン画面へのリンクを表示する。

### 簡易ワイヤーフレーム

```text
+------------------------------+
| ページが見つかりません       |
| URLや対象が正しいか確認して  |
| ください。                   |
| [みんなの活動へ戻る]         |
+------------------------------+
```

## 12. 画面遷移の全体像

```text
[トップ /]
   ├─ 未ログイン ─→ [ログイン] ←→ [ユーザー登録]
   │                    │              │
   │                    │成功          │登録成功
   │                    ↓              └→ [ログイン]
   └─ ログイン済み → [みんなの活動一覧]
                           ├→ [活動記録作成] ─成功→ [活動詳細]
                           ├→ [活動詳細] ─本人─┬→ [活動編集] ─成功→ [活動詳細]
                           │                   └→ [活動削除確認] ─成功→ [マイページ]
                           └→ [マイページ] ─→ [活動詳細]

[ログイン中の各画面] ─POSTログアウト→ [ログイン]
[保護画面への未認証アクセス] ─→ [ログイン]
[入力エラー] ─→ 入力値を保持して同じフォーム
[400 / 404 / 413 / 500] ─→ 状態に応じて活動一覧またはログイン
```

## 13. 画面設計上の共通ルール

- データやログイン状態を変更する操作は、GETでは実行しない。
- POSTフォームにはCSRFトークンを含める。
- POST成功後は303リダイレクトし、ブラウザーの再読み込みによる二重送信を防ぐ。
- 利用者の入力はテンプレート上でエスケープして表示する。
- 入力欄にはラベルを付け、プレースホルダーだけで意味を伝えない。
- 色だけに頼らず、文章でも成功・エラーの状態を伝える。
- 主なボタンは片手でも押しやすい大きさと間隔にする。
- 写真と清掃ルートは作成画面、編集画面、詳細画面だけで扱い、一覧・マイページには表示しない。
- 「ありがとう」は活動詳細だけに表示し、一覧・マイページには表示しない。
- 編集・削除ボタンは投稿者本人の活動詳細だけに表示する。
- 削除は専用確認画面のPOSTだけで実行し、GETではデータやファイルを変更しない。
