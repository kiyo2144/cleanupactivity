# ひろまち 画面設計書

## 1. この文書について

この文書は、「ひろまち」初版（MVP）の画面構成、表示内容、操作、画面遷移を定めるものです。要件は `docs/requirements.md`、ルートの処理は `docs/routes.md`を基準とします。

初版では、活動写真、活動記録の編集・削除、ランキング、交流機能を扱いません。画面はスマートフォンでの利用を優先します。

## 2. 共通レイアウト

| 項目 | 内容 |
| --- | --- |
| 目的 | 現在のログイン状態を示し、主要な画面へ迷わず移動できるようにする |
| ログイン | 不要。表示するナビゲーションはログイン状態で切り替える |
| URL・HTTPメソッド | 各画面のURLとメソッドに従う |
| Flaskエンドポイント | 各画面のエンドポイントに従う |
| テンプレート | `base.html` |

### 表示要素

- ヘッダーにアプリ名「ひろまち」を表示する。
- アプリ名は`main.index`へのリンクにする。
- 未ログイン時は「ログイン」「ユーザー登録」を表示する。
- ログイン中は「みんなの活動」「新しく記録する」「マイページ」を表示する。
- ログアウトはリンクではなく、CSRFトークンを含むPOSTフォームのボタンとして表示する。
- 成功、注意、エラーのフラッシュメッセージを本文の先頭に表示する。
- フォーム全体のエラーと項目別エラーを読み分けられる見た目にする。

### 正常時とエラー時の動作

- ナビゲーションを選ぶと、対応するGET画面へ移動する。
- ログアウトボタンを押すと、`POST /logout`を送信する。
- CSRF検証に失敗した場合は、ログアウトなどの処理を行わず400エラー画面を表示する。
- エラー画面でも、利用可能な戻り先を表示する。

### 簡易ワイヤーフレーム

```text
+----------------------------------+
| ひろまち                         |
| [みんなの活動] [記録] [マイページ]|
|                         [ログアウト]|
+----------------------------------+
| フラッシュメッセージ              |
+----------------------------------+
|                                  |
| 各画面の内容                      |
|                                  |
+----------------------------------+
```

スマートフォンでは、ナビゲーションを折り返して縦方向にも配置できるようにします。

## 3. ユーザー登録画面

| 項目 | 内容 |
| --- | --- |
| 目的 | 新しい利用者がアカウントを作成する |
| ログイン | 不要。ログイン済みの場合は活動一覧へ移動する |
| URL・HTTPメソッド | `GET /register`、`POST /register` |
| Flaskエンドポイント | `auth.register` |
| テンプレート | `auth/register.html` |

### 表示要素

- タイトル「ユーザー登録」
- ユーザー名：3～30文字
- 表示名：1～50文字
- パスワード：8～128文字
- パスワード（確認）
- 「登録する」ボタン
- 「ログインはこちら」リンク
- ユーザー名はログインに、表示名は活動画面での公開表示に使うことの説明

パスワード欄は入力内容を伏せて表示します。

### 正常時

- `GET`では空の登録フォームを表示する。
- `POST`の入力が有効ならユーザーを作成し、成功メッセージを付けてログイン画面へ303リダイレクトする。

### エラー時

- 必須項目、文字数、パスワード確認、ユーザー名の重複を検証する。
- エラーがある場合はユーザーを作成せず、HTTP 200で同じ画面を再表示する。
- ユーザー名と表示名は保持し、パスワード欄は空に戻す。
- DB障害などの予期しないエラーではユーザーを作成せず、500エラー画面を表示する。

### 画面遷移

- 登録成功 → ログイン画面
- 「ログインはこちら」 → ログイン画面
- 入力エラー → ユーザー登録画面

### 簡易ワイヤーフレーム

```text
+----------------------------+
| ユーザー登録               |
| ユーザー名 [____________]  |
| 表示名       [____________]  |
| パスワード   [____________]  |
| 確認用       [____________]  |
| [登録する]                 |
| ログインはこちら           |
+----------------------------+
```

## 4. ログイン画面

| 項目 | 内容 |
| --- | --- |
| 目的 | 登録済み利用者を認証し、アプリを利用できる状態にする |
| ログイン | 不要。ログイン済みの場合は活動一覧へ移動する |
| URL・HTTPメソッド | `GET /login`、`POST /login` |
| Flaskエンドポイント | `auth.login` |
| テンプレート | `auth/login.html` |

### 表示要素

- タイトル「ログイン」
- ユーザー名
- パスワード
- 「ログインする」ボタン
- 「ユーザー登録はこちら」リンク

### 正常時

- `GET`では空のログインフォームを表示する。
- `POST`で認証に成功したらログイン状態を開始し、活動一覧へ303リダイレクトする。

### エラー時

- 認証に失敗した場合はログイン状態を変更しない。
- ユーザー名とパスワードのどちらが誤っているか区別せず、「ユーザー名またはパスワードが正しくありません」と表示する。
- HTTP 200で同じ画面を再表示し、ユーザー名だけを保持する。
- DB障害などの予期しないエラーでは500エラー画面を表示する。

### 画面遷移

- ログイン成功 → みんなの活動一覧
- 「ユーザー登録はこちら」 → ユーザー登録画面
- 認証失敗 → ログイン画面

### 簡易ワイヤーフレーム

```text
+----------------------------+
| ログイン                   |
| ユーザー名 [____________]  |
| パスワード [____________]  |
| [ログインする]             |
| ユーザー登録はこちら       |
+----------------------------+
```

## 5. みんなの活動一覧画面

| 項目 | 内容 |
| --- | --- |
| 目的 | 登録利用者の清掃活動を共有し、地域の活動を見えるようにする |
| ログイン | 必要 |
| URL・HTTPメソッド | `GET /activities?page=N` |
| Flaskエンドポイント | `activities.index` |
| テンプレート | `activities/index.html` |

### 表示要素

- タイトル「みんなの活動」
- 「新しく記録する」ボタン
- 新しい順に並べた活動カード（1ページ10件）
- 各カードに活動日、投稿者の表示名、場所、所要時間、袋数、ゴミの種類を表示する。
- カード全体または「詳しく見る」リンクから活動詳細へ移動できるようにする。
- 2ページ以上ある場合は「前へ」「次へ」を表示する。移動先がないボタンは表示しない。

### 正常時

- `page`が省略された場合は1ページ目を表示する。
- 活動が0件の場合は「まだ活動記録がありません」と「最初の活動を記録する」ボタンを表示する。

### エラー時

- 未ログインの場合は案内メッセージを付けてログイン画面へリダイレクトする。
- `page`が1未満、整数でない、または存在する最終ページを超える場合は404エラー画面を表示する。
- ただし活動が0件の場合の`page=1`は正常画面として扱う。
- DB障害などの予期しないエラーでは500エラー画面を表示する。

### 画面遷移

- 「新しく記録する」 → 活動記録作成画面
- 活動カード → 対応する活動詳細画面
- 「前へ」「次へ」 → 活動一覧の前後ページ
- ナビゲーション「マイページ」 → マイページ
- ログアウト → `POST /logout` → ログイン画面

### 簡易ワイヤーフレーム

```text
+--------------------------------+
| みんなの活動                   |
| [新しく記録する]               |
| +----------------------------+ |
| | 10/11 佐藤さん             | |
| | フットパス北側 / 30分       | |
| | 1袋 / 燃えるごみ            | |
| |                 詳しく見る | |
| +----------------------------+ |
| +----------------------------+ |
| | 次の活動カード             | |
| +----------------------------+ |
| [前へ]                  [次へ] |
+--------------------------------+
```

## 6. 活動記録作成画面

| 項目 | 内容 |
| --- | --- |
| 目的 | 清掃活動後に、活動内容と成果を短時間で記録する |
| ログイン | 必要 |
| URL・HTTPメソッド | `GET /activities/new`、`POST /activities/new` |
| Flaskエンドポイント | `activities.create` |
| テンプレート | `activities/create.html` |

### 表示要素

- タイトル「清掃活動の記録」
- 活動日：必須。今日以前の日付
- 活動場所：必須。1～100文字
- 所要時間（分）：必須。1～1440の整数
- ゴミの袋数：必須。0～99の整数
- ゴミの種類：必須。次から一つ以上を選択
  - 燃えるごみ
  - プラスチック・ペットボトル
  - 缶・びん
  - その他
- コメント・感想：任意。500文字以内
- 活動場所へ自宅の番地などを書かないよう促す注意書き
- 「記録する」ボタン
- 「キャンセル」リンク

初版では写真入力欄を表示しません。すべての入力項目を1画面に配置します。

### 正常時

- `GET`では空のフォームを表示し、活動日の初期値には当日を設定する。
- `POST`の入力が有効ならログイン中の利用者の活動として保存する。
- 保存成功後、作成した活動詳細へ303リダイレクトし、成功メッセージを表示する。

### エラー時

- 必須項目、日付、文字数、数値範囲、ゴミの種類を検証する。
- エラーがある場合は保存せず、HTTP 200で入力内容を保持した同じ画面を再表示する。
- DB障害などの予期しないエラーでは保存処理を取り消し、500エラー画面を表示する。
- 未ログインの場合はログイン画面へリダイレクトする。

### 画面遷移

- 保存成功 → 作成した活動の詳細画面
- 「キャンセル」 → みんなの活動一覧
- 入力エラー → 活動記録作成画面

### 簡易ワイヤーフレーム

| 活動場所      [______________]  |
| 所要時間（分）[____]            |
| ゴミの袋数    [____]            |
| ゴミの種類                     |
| [ ] 燃えるごみ                  |
| [ ] プラスチック・ペットボトル  |
| [ ] 缶・びん  [ ] その他        |

## 9. エラー画面

### 9.1 400 Bad Request

| 項目 | 内容 |
| --- | --- |
| 目的 | CSRFエラーなど、受け付けられないリクエストであることを知らせる |
| ログイン | 不要 |
| URL・HTTPメソッド | エラーが発生したURLとメソッド |
| Flaskエンドポイント | 400エラーハンドラー |
| テンプレート | `errors/400.html` |

- 「リクエストを処理できませんでした」と、再操作を促す案内を表示する。
- データやログイン状態は変更しない。
- ログイン中は活動一覧、未ログイン時はログイン画面へのリンクを表示する。

### 9.2 404 Not Found

| 項目 | 内容 |
| --- | --- |
| 目的 | 指定したページ、活動、一覧ページが存在しないことを知らせる |
| ログイン | 不要 |
| URL・HTTPメソッド | 存在しないURL、または存在しない対象を指定したGET |
| Flaskエンドポイント | 404エラーハンドラー |
| テンプレート | `errors/404.html` |

- 「ページが見つかりません」と表示する。
- ログイン中は活動一覧、未ログイン時はログイン画面へのリンクを表示する。

### 9.3 500 Internal Server Error

| 項目 | 内容 |
| --- | --- |
| 目的 | 予期しない障害が発生し、処理を完了できなかったことを知らせる |
| ログイン | 不要 |
| URL・HTTPメソッド | エラーが発生したURLとメソッド |
| Flaskエンドポイント | 500エラーハンドラー |
| テンプレート | `errors/500.html` |

- 「処理中にエラーが発生しました」と表示し、内部情報や例外内容は表示しない。
- 更新処理中だった場合は中途半端な変更を残さない。
- ログイン中は活動一覧、未ログイン時はログイン画面へのリンクを表示する。

### 簡易ワイヤーフレーム

```text
+------------------------------+
| ページが見つかりません       |
| URLや対象が正しいか確認して  |
| ください。                   |
| [みんなの活動へ戻る]         |
+------------------------------+
```

## 10. 画面遷移の全体像

```text
[トップ /]
   ├─ 未ログイン ─→ [ログイン] ←→ [ユーザー登録]
   │                    │              │
   │                    │成功          │登録成功
   │                    ↓              └→ [ログイン]
   └─ ログイン済み → [みんなの活動一覧]
                           ├→ [活動記録作成] ─成功→ [活動詳細]
                           ├→ [活動詳細]
                           └→ [マイページ] ─→ [活動詳細]

[ログイン中の各画面] ─POSTログアウト→ [ログイン]
[保護画面への未認証アクセス] ─→ [ログイン]
[入力エラー] ─→ 入力値を保持して同じフォーム
[400 / 404 / 500] ─→ 状態に応じて活動一覧またはログイン
```

## 11. 画面設計上の共通ルール

- データやログイン状態を変更する操作は、GETでは実行しない。
- POSTフォームにはCSRFトークンを含める。
- POST成功後は303リダイレクトし、ブラウザーの再読み込みによる二重送信を防ぐ。
- 利用者の入力はテンプレート上でエスケープして表示する。
- 入力欄にはラベルを付け、プレースホルダーだけで意味を伝えない。
- 色だけに頼らず、文章でも成功・エラーの状態を伝える。
- 主なボタンは片手でも押しやすい大きさと間隔にする。
- 写真、編集、削除に関する部品は初版の画面に表示しない。
